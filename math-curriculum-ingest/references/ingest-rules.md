# 题库导入 · 细则全文

本文件按需加载。SKILL.md 里是梗概，这里回答"为什么必须半自动"。

## 一、为什么"全自动提炼母题"做不到

**核心矛盾：判"是不是同一个母题"靠的是"数学结构"，而脚本只能看"文本"。**

| 情形 | 文本像吗 | 是同一母题吗 | 脚本能判吗 |
|---|---|---|---|
| 同一道题换数字 | **极像** | 是 | ✅ 能 |
| 同一母题换情境（红球→男生） | **不像** | 是 | ❌ **不能** |
| 同一母题换问法（正问↔反问） | 部分像 | 是 | ⚠️ 有时能 |
| 两道无关题但都是"在△ABC中…" | 有点像 | 否 | ⚠️ 可能误报 |

**第二行就是死结**：换情境是"变式"的核心手段，而一换情境文本就变了 ——
**脚本恰好在这一类上失明，而这一类恰恰最重要。**

> 所以正确答案不是"做个更强的脚本"，而是：
> **脚本做粗筛（挡掉 80% 机械比对），人做定稿（判断那 20% 的关键）。**

### 那还能不能借 LLM 帮忙？

**能，但要小心。** LLM 判"是不是同一母题"比纯文本脚本强得多，
但它**会编**（把两道无关题说成同源，还给你编个理由）。

推荐用法：
- **让 LLM 只看"候选簇"**（脚本已经缩小了范围），别让它扫全库；
- **要求它给出判据**（"这两题同用韦达定理求弦长"），**并抽查**；
- **最终仍要人过一眼**（尤其 `needs_human_check: true` 的簇）。

## 二、阈值怎么调

默认 `--thresh 0.55`。调参看两个信号：

| 现象 | 说明 | 动作 |
|---|---|---|
| **同类的题没聚到一起**（漏聚） | 阈值太高 | 调低（试 0.45） |
| **明显不同的题聚到一簇**（误聚） | 阈值太低 | 调高（试 0.65） |

**判断依据永远是"抽查"**：拿几组你确定是/不是同一母题的题，
看它们落在阈值的哪一侧。**别凭感觉调。**

> 一次调一个方向，调完重新抽查。**改阈值 = 改判据，必须重新验证。**

## 三、复核怎么记录（让"有没有收敛"可验证）

`clusters.json` 里每簇有这些字段：

```json
{
  "size": 2,
  "representative": "q1",
  "members": ["q1", "q2"],
  "avg_similarity": 0.668,
  "weakest_pair_sim": 0.668,
  "needs_human_check": false,
  "verified": false,
  "note": ""
}
```

复核时**只动两个字段**：

- `verified` → `true`（确认是同一母题）或保持 `false`
- `note` → 写上母题名 / 拆分说明 / 判据

**复核完成后自检**：`verified: true` 的簇数 ＋ 新定的孤题母题数 ＝ 最终母题总数。
**这个数要能和知识地图里的节点数对上。**

> **教训**：只声明"复核了"是验不了的。**必须留下可核对的字段。**
> 一个只写"已整理完成"的清单，等于没整理。

## 四、版权与数据边界（**红线**）

| 材料 | 能不能进你的题库 | 能不能随技能分发 |
|---|---|---|
| **教材例题** | ✅ 自己用可以 | ❌ **不能打包分发** |
| **真题** | ✅ 自己用可以 | ⚠️ **建议只存"锚点"（出处），不复制题干** |
| 自己出的题 | ✅ | ✅ |
| 第三方题库 | ⚠️ 看授权 | ❌ 通常不能 |

**本技能只处理"你有权处理"的题目。** 分享技能时，**示例数据必须是虚构的** ——
仓库里 `examples/raw/` 那 6 道题就是随手编的，不含任何真实教材/真题原文。

## 五、常见错法

| 错法 | 后果 | 修法 |
|---|---|---|
| 把 `clusters.json` 直接当母题清单用 | 母题数虚高/虚低，后续全错 | 必须过第 3 步人工定稿 |
| 一次调阈值调很多 | 不知道是哪一步起的作用 | 一次一档，调完抽查 |
| 只看"聚成几簇"，不看孤题 | 漏掉"新母题" | 孤题逐题判 |
| 复核不留字段 | 无法核对、无法审计 | 填 `verified` / `note` |
| 示例数据用了真实教材/真题 | 侵权 | 用虚构题 |
