# 知识地图 · 建图准则全文

本文件按需加载。SKILL.md 里是梗概，这里是细则。

## 一、为什么要"可校验"

一张手画的知识地图，看起来都对 —— **因为看不出错**。

真实的坑：

- **环**：`因式分解 ← 一元二次方程` 又 `一元二次方程 ← 因式分解`。
  写的人心里想的是"这俩互相用"，但**前置关系是偏序，不能互相依赖**。
  一旦成环，"该先补什么"就**无解**（拓扑排序直接失败）。
- **悬空前置**：prereq 里写了 `K-分母有理化`，但 `nodes` 里根本没有这个节点。
  于是追链时**静默跳过** —— 你以为补链完整，其实少了一环。
- **孤立点**：新加的考点忘了连关系，它就成了地图外的孤岛，
  任何一条学习路径都不会带上它。

**这三种错，人眼几乎查不出，代码一秒就能。** 所以 `atlas.py validate` 是硬门槛。

## 二、建图三条准则

### 准则 1：前置 = 必要，相关 = 常见（别混）

| | 判据 | 放哪 |
|---|---|---|
| **前置** | **不会它，就学不动它** | `prereq` |
| **相关** | 常一起考 / 常一起用，但**可以独立学** | `cooccur` |

**自测**：「如果学生完全没学过 A，能不能直接学 B？」
- 不能 → A 是 B 的前置。
- 能，只是会费劲 → A 和 B 只是**相关**。

> 常见误判：把"常一起用"当成"必须先学"。
> 例：`导数` 和 `函数单调性` —— 单调性是导数讨论的对象，
> 但学生**可以先学单调性（不靠导数）**。所以它们是**相关**，不是前置。

### 准则 2：地图要"跨章节"，不是"照抄目录"

有价值的关系是**跨章节的依赖**，例如：

- `一元二次不等式` ← `二次函数`（不同章节，但后者是前者的图像语言）
- `概率的加法公式` ← `集合的并集`（跨模块）

照抄教材目录做出来的图**没有信息量**（目录本身就是顺序的）。
地图的价值在**把目录掩盖掉的依赖显式化**。

### 准则 3：粒度一致

不要一半"整个模块"、一半"单个技巧"。两种粒度混在一起，
分层结果会失真（"立体几何"和"韦达定理"不是同一层级的东西）。

**选一种粒度，全图统一。**

## 三、与其他技能怎么配合

```
math-curriculum-ingest   →  产出考点清单（id + 名称 + 教材锚点）
        ↓
math-knowledge-atlas     →  把这些考点连成图（前置 / 常同框）
        ↓
math-mastery-scheduler   →  按图上的依赖，决定"先补哪个、再练哪个"
        ↓
math-paper-forge         →  按调度结果出卷（考点用同一套 id）
```

**关键：四个技能用同一套考点 id。** 这样"图上的节点""卷上的题"
"看板上的考点"指的是同一个东西，不会各说各话。

## 四、常见错法清单

| 错法 | 症状 | 修法 |
|---|---|---|
| 把相关当前置 | `validate` 报环 | 挪到 `cooccur` |
| 前置节点没建 | 报"悬空前置" | 补 node 或删该前置 |
| 忘了连关系 | 报"孤立点" | 补关系；若确为独立模块，可在报告里注明 |
| 粒度混乱 | 分层结果怪（地基层混进高阶内容） | 统一粒度后重跑 |
| 照抄目录 | 图很"正确"但没用 | 只保留**跨章节**的依赖边 |

## 五、输出形态

1. **`mermaid`** —— 贴 GitHub README / Issue / PR 直接渲染，零依赖。
2. **`levels`** —— 文本分层，用于排教学/复习顺序。
3. **`path`** —— 前置闭包链，用于"这个学生该回补哪里"。
4. **`cooccur`** —— 常同框组合，用于设计"并联辨析题"
   （把两个易混考点放一道题里，逼学生区分 —— 与 scheduler 的"交错练习"配套）。
