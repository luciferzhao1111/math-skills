# 掌握度调度（math-mastery-scheduler）

**一句话**：把"这次做对了，要不要加难度？"从**感觉**变成**按证据算**。

三根支柱（每一条都是被真实事故踩出来的）：

1. **难度档 ≠ 状态 ≠ 事件** —— 三个正交维度，**禁止混用**（§二）。
2. **升档要证据齐** —— 连对 2 次**只是"进入探测"**，不是升档；正式升档要三类证据齐（§三、§四）。
3. **复现要变着法儿来** —— 不许只换数字；同日同考点是硬红线（§五）。

---

## 一、什么时候用 / 不用

| 用户说 | 走这条 |
|---|---|
| "他这次做对了，下次还练这个吗 / 要不要加难度？" | §四 规则 + `scripts/scheduler.py` |
| "帮我排一下复习计划 / 哪些考点该复现了？" | §五 间隔规则 + `scheduler.py review` |
| "错题本越做越厚，怎么收口？" | §五 铁律 6（销号机制） |
| "出一份卷子" | **不用本技能**（用 `math-paper-forge`） |
| "批改卷子 / 讲错题" | **不用本技能**（用 `math-grader`） |

---

## 二、三个正交维度（先搞懂这个，否则必错）

| 维度 | 是什么 | 取值 |
|---|---|---|
| **难度档 `level`** | 学生**当前正式能力档** | ★ / ★★ / ★★★ / ★★★★ |
| **状态 `state`** | 当前**处理策略** | 待补台阶 / 纠正中 / 攻坚中 / 保温 / 已掌握 |
| **事件 `event`** | 本次训练**发生了什么** | 判定题(Judgment) / 探测题(Probe) / 周练 |

**三条禁令**：

- **三者各自独立存储，不得互相代入。**
- **状态由当前证据计算，不沿固定流水线推进** —— 允许 `攻坚中 → 待补台阶`、`保温 → 回流`、
  `纠正中 → 重新补强` 等**回流**。
- **`level` ≠ `target_level`**：`target_level` 是本阶段要求**稳定达到**的档。
  **`level` 连对很多次，也只说明"当前档稳"，不等于达标。**
- **Step ≠ 难度档**：内部解法链的 Step 只描述"这道题的解法有多长"，
  ★ 描述"学生的能力档"，**禁止一一映射**（不许写"Step2 = ★★"）。

---

## 三、四档证据（描述掌握，只有这四个词）

| 证据 | 含义 |
|---|---|
| **E1 本轮通过** | 刚做完、当场做对（可能看过提示/解析） |
| **E2 即时独立复现** | 换个题、**无人提示**、独立做对 |
| **E3 同级迁移** | 换数字/问法/情境后，**独立**做对且关键理由对 |
| **E4 延迟复现** | 隔 ≥7 天再做，**仍**独立做对 |

**升档要的证据齐 = E2 ＋ E3 ＋ E4 全部通过。**

> **语言纪律**：描述掌握**只用这四个词**。**禁止**"全部攻克""已掌握"这类断言 ——
> **做对 ≠ 掌握**；`E1 通过` 离 `E2` 还差一次"独立"。

## 四、难度升降规则（针对**当前档判定题**）

| 触发条件 | 动作 |
|---|---|
| **判对（连对 1 次）** | 档位不变，加 1 道**变式**巩固 |
| **同档连对 2 次** | **进入「升档探测」(Probe)** —— **不自动升档** |
| **探测通过**（且 E2＋E3＋E4 齐） | **才 +1★**，连对清零 |
| **判错 · 计算失误** | **档位冻结**（不升不降），连对清零，追加**限时计算专项** |
| **判错 · 概念混淆/思路卡壳（该档首次）** | **档位预警**（**不降档**），连对清零，回**前置单点题补台阶** ＋ 追加 1 道同档补强 |
| **该档再次出现概念/思路错（同档累计 ≥2 次）** | **−1★**，连对清零，回前置单点题补台阶 |
| **已到 ★ 仍错** | 退回**课本概念 ＋ 教材例题**，先建地基 |

**三条硬性约束**：

- **连对定义**：同一难度档下「**判定题**」连续全对的次数；**升档后从 0 重计，跨档不累计**。
- **升档依据必填**：任何 `+1★` 必须写清「**同级连对次数 ＋ 最后一次证据（日期·题号·结果）**」；
  写不出依据 → **不许升档**。
- **降档也要重复证据**：若升档要"连对 2 ＋ 探测 ＋ 三证据齐"，而降档只需单次错，
  **档位会系统性下沉**。故降档要**同档累计 ≥2 次**概念/思路错。

**探测题（Probe）规则**：当前档升档后，同卷**更高档题**出错 →
**只按错因追加专项，不撤销升档、不额外降档、不碰连对。**

> **只有「当前档判定题」影响正式档位；Probe 只探测。** 这是最容易搞错的一条。

**状态「纠正中」的退出条件**（防长期挂起）：
- E4 延迟复现**通过** → 攻坚中
- E4 **失败且概念/思路错** → 待补台阶
- E4 **失败且计算错** → 档位保持 ＋ 计算专项

## 五、间隔重复与复现设计

### 5.1 什么时候再考（时间规则）

```
新考点学完后：第 1 天 → 第 3 天 → 第 7 天 → 第 14 天 → 结课抽查
```

> ⚠️ **这组天数是"系统默认参数"，不是学习科学定律。** 间隔学习确有实证支持
> （分散复习优于集中突击、检索练习优于重读），但**不支持**"某组固定天数对所有人都成立"。
> **可依实测效果与剩余时间调整。** 「同一考点最多复现 3 次」同理 —— 那是**资源保护阈值**。

> ⚠️ **复现周期 ≠ 难度升降**：这组天数只管"**什么时候再考**"；
> **正式升降档只执行 §四**。**禁止**使用"答对就跳一档间隔／答错就退回上一档"这类简化规则。

### 5.2 复现怎么"变"（九条铁律，违者不得发卷）

> **事故来源**：某天发了两份卷，**10 个考点全部重合**，学生原话"很多题目反复在做，烦死了"。
> 这不是学生怕苦，是设计错了 —— 把"复现"做成了"换个数字再考一遍"，间隔还被压成 0 天。
> **更根本的漏洞**：只规定了"什么时候再考"，**没规定"每次怎么变"**。

| # | 铁律 | 为什么 |
|:--:|---|---|
| 1 | **同日同考点禁令**：同一考点当天不得出现两次（跨卷也算）；同日多份卷的考点集**必须不相交** | 间隔为 0 ＝ 集中重复，低效且引发反感 |
| 2 | **最小间隔 ≥2 次练习**（目标 3–7）；**禁止**把 D1→D3→D7→D14 压成"每天一考" | 最优间隔 ≈ 目标保持期的 10–20% |
| 3 | **同卷内同一考点 ≤1 题** | 交错练习，延迟测验上显著优于集中 |
| 4 | **复现形式阶梯（不许只换数字）**：第 1 次＝换数字；第 2 次＝**换问法或换表征**；第 3 次＝**换情境 ＋ 与相邻概念并列辨析**。**禁止连续两次都用"换数字"** | 在"变"中比较出"不变" |
| 5 | **出现上限 3 次**：同一考点最多**复现** 3 次；第 3 次仍错 → **不再出同类题**，转"地基闸门"，换策略而非加题量 | 三次仍错＝顽固分子。⚠️「结课抽查／掌握后抽查」是**验收性抽查，不计入这 3 次** |
| 6 | **销号（毕业）机制**：**独立复现通过 ＋ 同级迁移通过 ＋ ≥1 次延迟复现通过** → 移出复现池，改用**可增长量**公示（如"已锁死地板题位 X/8"） | 错题本"越用越薄"；进度可见是对抗厌烦的核心 |
| 7 | **新鲜感配额**：每份卷 **≥50% 的题**必须是**没做过的考点或情境**；卷首写明"今天有 N 个新东西" | 学生反感的不是重复，是"**看不到进展的重复**" |
| 8 | **「订正」与「复现」分离**：**原题重做只在订正环节**（当天/次日闭卷重做 1 遍），**不进练习卷**；练习卷只放**变式** | 原题重做＝识别熟悉文本，产生"我会了"的错觉 |
| 9 | **复现必带"提取尝试"**：先独立做、再看解析；**不许先给提示** | 检索练习：反复阅读 28% vs 间隔＋自测 81% |

> **反面清单（严禁）**：① 同日两卷同考点；② 连续两天同考点；③ 只换数字当"变式"；
> ④ 同一考点第 4 次出现；⑤ 练习卷里出现原题。

### 5.3 周期周练（累积检测）

**每 5–7 个「训练日」后插 1 次周练（累积卷）。**
（一个"训练日" ＝ 一个完成整套练习的日子，**不是一份卷**。）

- 只抽**已学考点**做混合抽取，**不引入全新难点**；
- 题量少（约 10 题 / 50 分，限时按实测校准）；
- 从错题记录里挑 1–2 个已复现过的考点**回炉**。

## 六、调度优先级（**不可颠倒**）

```
安全性 ＞ 闭环完成 ＞ 独立复现 ＞ 迁移 ＞ 升档 ＞ 题量
```

> 意思是：**"加难度"排在最后**。宁可少练两道题，也不能跳过"独立性验证"去升档。

**混合出题**：每份卷 ≥2 个考点（1 攻坚 ＋ 1 保温）；**禁止同考点连排**；攻坚放前段。

## 七、脚本

`scripts/scheduler.py` —— 把上面的规则写成**可执行的判定引擎**，让"升不升档"是**算出来的**。

```bash
# 看每个考点当前该怎么调（读 state.json）
python3 scripts/scheduler.py state.json review

# 应用一次作答结果，输出新状态与下一动作
python3 scripts/scheduler.py state.json apply M-代数-01 --result correct --judgment
python3 scripts/scheduler.py state.json apply M-代数-01 --result wrong --cause 概念混淆 --judgment
```

状态文件 `state.json` 的字段见 `examples/state.example.json`。

> **它只做一件事**：把 §四 的规则表逐条实现，
> 并**在内置的规则自检里**验证 —— 例如"连对 2 次**不得**输出升档"、
> "单次概念错**不得**降档"、"Probe 出错**不得**动正式档位"。
