# 讲题视频 · 脚本规范与合成纪律（v4.19）

> **定位**：视频不是"把详解念一遍"，它是**处置阶梯的末档**。本文件规定：什么时候才配做视频、脚本长什么样、合成时哪几件事必错。
> **上位文档**：规则全集 v4.19 §5.9.1c（详细讲解稿）＋处置阶梯（视频定位）。

---

## 1. 使用门槛（先过这一关，否则免谈）

| 门槛 | 规则 |
|---|---|
| **启用条件** | 仅当上一档（**孩子讲给家长听**）仍无效时才用。**跳过更便宜的处置（换台阶/换锚点/讲题）直接上视频 = 违规** |
| **用量上限** | 每周 **≤1 个**（分镜＋动画＋渲染＋配音成本高） |
| **替换性** | 看视频**替代**"反复看详解/家长再讲一遍"——三者不叠加，否则就是"追加" |
| **适用考点** | 只做"**动起来才看得懂**"的：几何变换、函数图像、圆锥曲线、立体展开。**纯代数技巧不做视频**（静态详解更清楚） |
| **时长** | 一道题 **1–3 分钟**（90–120 秒最佳；<60 秒显得敷衍） |
| **配音依赖** | 需 TTS；无 key 可出免费预览版（有动画＋字幕、无配音） |

## 2. 口播稿：交付物是"自包含 md"，不是视频本身

### 2.1 触发条件（任一即写）

① 家长/学生说"讲得太简单、看不懂"；② **覆盖卷的新考点首次出现就做错**（尤其空白/没起手）；③ 只有"完全不会/空白"且属新题型。

### 2.2 两部分结构

**第一部分 · 事实底稿（7 项，一项都不能少）** —— 给下游 AI/视频工具用，可直接复制：

1. 出处与学情（含**学生逐字作答**与错因）
2. 题目（**LaTeX ＋ 纯文本双写**）
3. **完整标准解答**（一段到底、不跳步）
4. 答案
5. 验算
6. 变式与答案
7. "本文件怎么读"（告诉下游每列是什么）

**第二部分 · 逐句脚本** —— 按「幕 × 句」给**三列表格**：**口播（直接念）｜字幕（画面字幕）｜画面提示**。

### 2.3 四条铁律

| # | 铁律 | 为什么 |
|:--:|---|---|
| 1 | **"起手动作"必须显式**：先给这类题的**通用第一步**（动词开头），再逐步演示 | 事故：孩子只写了个 `lim` 就停住——病根是"不知道该往哪儿动"，不是不会算 |
| 2 | **每个数值都由脚本算出**，包括代入试探值 | 事故：手写 `2.0085 / 2.00085`，实为 `1.9368 / 1.9935`，且逼近方向写反 |
| 3 | **口诀 ＋ 易错点 ＋ 检验** 三件套必带 | 视频的价值在"下次遇到怎么起手"，不在"这道题算完了" |
| 4 | **口播列必须是能直接念的中文**：数字写汉字，无 `= ^ ( ) √` | 否则会花钱合成出错误读音（"三分之派"念成"三分之 P I"） |

### 2.4 工程参数（实证样本：10 幕 / 35 句）

| 参数 | 值 |
|---|---|
| 幕数 | **10 幕**：intro / 概念 / 判型 / 起手 / 变形 / 收口 / 口诀 / 检验 / 易错 / outro（每幕 2–4 句） |
| 句数 | **35 句**（一句 = 一个镜头） |
| 每句口播 | **≤36 个汉字**（避免字幕折两行）；一句只讲一件事 |
| 画面 | 16:9 / 1920×1080 / 30fps / 手绘笔记本风格 |
| 分区 | 内容 y ≤ 860；底部 y≈914–1044 留字幕；图形放左半（x 60–900），推导写右侧横线板 |
| 字幕 | 中文为主（中英双语按稿逐句加）；公式用 LaTeX 渲染，**不要纯文本**（`n²` 会变 `n☒`） |
| 强调 | 口诀、起手动作、四步法各留一次"盖章"式强调 |

### 2.5 结构自检（默认执行机制）

```
python3 check_lecture.py <稿.md>
```

七小节缺一、幕数 <6、句数 <15、口播含数字/符号、或没写"起手动作" → **exit=1，不得交付**。

## 3. 合成流水线（离线）

```
文案分场景 → TTS 逐场景配音 → ffprobe 量时长
  → 场景内按字数比例把时长分给每句字幕（一句一画面）
  → 图形逐帧渲染（立体图：真旋转，每帧重算隐藏棱）
  → 静止版面（1920×1080：图形卡留空 + 推导面板 + 双语字幕 + 进度条）
  → 把旋转序列按时间轴叠进图形卡 → concat 拼接
  → 配音拼接 → 合轨 → 压到 <8MB
```

**两条可替换的 TTS 路线**（渲染层按环境选型）：
- `GLM-TTS`（智谱，需 API key，音色自然）
- `edge-tts`（微软在线，**需联网、无需 key**，本机实测滤镜/编码器齐备）
- 无 key 时出**免费预览版**（动画＋字幕、无配音）——**不得因此跳过结构自检**

**时长分配不能平均**：

```python
weights = [max(4, len(cn)) for cn, _ in lines]      # 每句中文字数，最少给 4
dt_i = scene_duration * weights[i] / sum(weights)   # 每句 = 一个镜头
```

- **不要逐句调 TTS**（语调会碎，像机器人在念条目）；整场景合成、再按字数切时间。
- 用 `ffprobe -show_entries format=duration -of default=nw=1:nk=1` 精确取时长，别估算。
- 语速 `rate="+12%"`，中文讲解听着刚好。

## 4. 五个必踩的坑（全是用户当面否过或实测踩过的）

### 坑 1 · 字幕下标变方框
微软雅黑没有 U+2080–2089 下标字形 → 字幕 `A₁B` 印成 `A□B`。
**解法**：逐字绘制 + 遇下标换小字号下沉（下标字号 ≈0.68×，y 下沉 ≈0.23×），别整串丢给 `ImageDraw.text`。
**注意分工**：**旁白文本反而写 `A一B`** —— 中文 TTS 读成"A 一 B"，正是学生的口语读法。

### 坑 2 · 别给全片加推近（用户原话否过）
> "为什么你这个视频，不停的在画面缩小变大缩小变大的，看着很累，什么目的？"

病因：一句字幕 = 一个镜头，每个镜头都推一次，96 秒里二十几次呼吸式缩放。
**默认画面完全静止**，动态只留给两处有信息量的变化：

| 允许动 | 为什么 |
|---|---|
| 推导面板逐行揭示（每行给 `reveal_at`，当前行加 tint 底色） | 内容在推进，跟得上 |
| 图形按讲解换角度 | 同一物体的新视角 = 新信息 |

### 坑 3 · 立体图必须真旋转（逐帧重算）
① 每帧重算可见面/隐藏棱（法向量与视线点积 >0 为可见面；棱被两个可见面共享才画实线）；
② **全片用同一个裁剪框**（先采样几十帧求并集 bbox），逐帧自适应裁剪会让物体忽大忽小，比推近更晕；
③ alpha 合成用 `alpha_composite`，**不要 `paste`**（RGBA 当 mask 会让淡蓝面全发灰）。

### 坑 4 · 叠加坐标按最终版面尺寸算
版面若先按 2× 渲染再 resize，叠加就必须用最终 1080p 坐标；按 2× 算会把图形放大一倍冲出卡片（实测：立方体糊在推导面板上）。

### 坑 5 · 压体积
1080p 96 秒 crf20 ≈11MB → crf26 ≈7MB。base64 内联进 HTML 还要 ×1.33，**超过 8MB 就该压**：
`-c:v libx264 -crf 26 -preset slow -pix_fmt yuv420p -c:a copy`。

## 5. 版面骨架（1080p，效果最好的一版）

```
┌──────────────────────────────────────────────┐
│ [品牌 chip]                        [场景标签]│  y 48–88
│ 场景标题                                     │  y 118，38px bold
│ ─────────────────────────────                │  y 178 细线 + 前 58px 强调色
│ ┌──────────────────┐  ┌───────────────────┐  │
│ │ 图形卡（透明叠图）│  │ 推导面板（逐行揭示）│  │  y 208–800
│ └──────────────────┘  └───────────────────┘  │
│ ┃ 中文字幕（33px bold）                      │  y 846–1000
│ │ 英文字幕（19px muted）                     │
│ ▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░  4/5              │  y 1034
└──────────────────────────────────────────────┘
```

- 图形用 matplotlib 画好、`transparent=True` 存 PNG，PIL **按比例缩放**贴进图形卡（`min(maxw/w, maxh/h)`，别拉伸）。
- 每个场景换一个强调色（indigo / rose / violet / green），观众能感知"进入下一段"。
- **图形卡底部留一条脚注**（约 17px）：① 示例题难度说明；② 素材/技能出处致意——这条用户会主动要，一开始就留位置。
